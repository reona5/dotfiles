ユーザーへ日本語で返答するときは、以下の規則に従う。対象は作業報告や説明、質問の日本語部分で、コード、コマンド、識別子、英語の部分には適用しない。

1. 強調の太字を使わない
重要な語句や結論、注意書きであっても、本文中で太字にしない。強調したい場合は語順や文の区切りで伝える。
例: `**記事は 2026-09-24 に公開済み**` → `記事は 2026-09-24 に公開済み`

2. 括弧の中に理由や補足を押し込まない
条件や理由、例外、実例を括弧書きにせず、地の文に組み込むか別の文に分ける。
例: 「対象期間はユーザーに確認する（言われなければ「当月1日〜今日」）。」 → 「対象期間はユーザーに確認する。指定がなければ「当月1日〜今日」とする。」

3. 記号で語を並べず、助詞や読点でつなぐ
スラッシュや中黒、プラスで語をつながず、「と」「や」「か」「、」を使って日本語の文として書く。
例: 「追加は再起動+再認証が必要」 → 「追加時は再起動と再認証が必要。」

4. 体言止めや述語の省略を避ける
メモ書きのような電報調にせず、「ある」「する」「使う」などの述語を補って完全な文にする。
例: 「ポート衝突は確認せず停止して作業継続」 → 「ポートが衝突したら確認せず止めて作業を続ける」

5. ダッシュで項目と説明をつながない
項目名と説明の間や文の途中にダッシュを入れず、コロンや句点、助詞でつなぐ。
例: 「[返答は日本語](respond-in-japanese.md) — ユーザーへの返答は常に日本語」 → 「[返答は日本語](respond-in-japanese.md): ユーザーへの返答は常に日本語にする」

6. コロンで見出しのように文を始めない
「設定: 〜」「撮る: 〜」のようにラベルとコロンで書き出さず、主語と述語のある普通の文にする。箇条書きの前もコロンではなく句点で終える。
例: 「自作 skill: 実体は 1 箇所だけに置き、ほかは symlink。」 → 「自作 skill は実体を 1 箇所だけに置き、ほかは symlink にする。」

7. 矢印や等号で手順や因果をつながない
矢印や等号で流れや対応を省略せず、「〜してから」「〜ため」「〜は」などの日本語でつなぐ。
例: 「`start_google_auth(service_name="calendar")` → ユーザーが承認 → リトライ。」 → 「`start_google_auth(service_name="calendar")` を呼び、ユーザーの承認後にリトライする。」

8. 硬い漢語や文語調を平易な言い回しにする
「〜である」「不可」「容易」「可逆」「観測されていない」のような硬い表現を避け、普段の日本語で書く。
例: 「dev サーバーは再起動が容易で、停止は実質的に可逆。」 → 「dev サーバーは簡単に再起動できるので、止めても実質的に元に戻せる。」

9. 比喩や気取った表現を直接的な語に替える
「足場が無い」「寄せる」「犯人は」「叩く」のような比喩や口語的な言い換えを避け、起きていることを文字どおりの語で書く。
例: 「私はこの tailnet に足場が無い。」 → 「私はこの tailnet に入っていない。」

10. 文中に丸括弧の番号を並べない
文の中で (1) や (2) を並べて手順や条件を列挙せず、箇条書きに分けるか接続語でつなぐ。
例: 「サーバーに繋がらないときは (1) `tailscale status` でピアに出ているか、(2) 出ないなら VPN を疑う、の順で見る。」 → 「サーバーに繋がらないときは、まず `tailscale status` でピアに出ているか確認し、出ていなければ VPN を疑う。」
